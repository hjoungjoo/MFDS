# 누적 실측 기반 최적화 통합 계획

2026-09-15. 기준 MF `da9743a`, PiFinder `21eee645`.
사용자는 재부팅 후 구름 병렬 RAW 검출 p95 약 6ms 증가를 허용하고,
지금까지의 결과를 종합한 최적화를 요청했다.

## 유지할 기본값

MF4p(전체 1/4→별 주변 1/2), response 순서, 최대 48개, sigma4.5,
별도 native MF 프로세스/memfd, MF 실패·후보 부족 때만 SEP,
개선 Tetra3 검색, auto 전처리(스케일 3작업자/시간 창 5장),
단일 프레임 별 후보 마스크 재사용을 유지한다.
RAW 실패·정렬·보정 때 같은 프레임 전처리 대기도 유지한다.
통합 Python 시험 프로세스, 항상 전처리 anchor, 원본 재측정, 1/8 탐색은
기본으로 승격하지 않는다. 기존 비교 도구와 옵션은 보존한다.

## 추가 검증할 변경

1. 양자화 이후 신호 가중치를 시간 창에 넣을 때 한 번 적용한다.
   기존 신호 배열 대신 같은 float32 크기의 가중 신호를 보관해
   과거 프레임의 나눗셈/clip/곱셈을 반복하지 않는다. 합산 순서는 유지한다.
2. 연결 성분별 허용 표를 label 번호로 직접 조회한다. 후보 번호 목록과
   전체 영상의 membership 검사를 반복 생성하지 않는다.
3. 테스트 실행 설정에 검출·스케줄·transport·검색 기본값을 함께 명시한다.
   검출 프로필만 선택하는 기존 비교 API는 transport/search를 덮어쓰지 않는다.

추가 누적 영상 캐시 없이 검증하며 기존 자료형·숫자 결과를 보존해야 한다.
단위 테스트, 같은 입력의 픽셀/evidence/좌표/진단 비교, 기록 RAW→솔빙 A/B,
실제 auto 정책 재생을 실행한다. 성능 검사는 테스트/타입 검사와 겹치지 않는다.
재부팅 전과 후의 절대 시간 차이를 개선 효과로 계산하지 않고 같은 실행의
이전/개선 비교를 사용한다. 상세 영상·좌표는 로컬, 요약만 푸시한다.

재부팅 후 확인: RAM available 4972MiB(약 4.86GiB), swap0, uptime3분.
운영 PiFinder PID714/Cedar PID704, 운영 checkout 경로, DropInPaths 없음.
서비스·부팅·카메라·마운드는 변경하지 않는다. 두 승인된 테스트 브랜치에
계획/구현/결과를 나눠 커밋·푸시한다.
