# 검토 사항 반영 결과

기준: PiFinder `c7d9e0b4`, MF `3e7f045`. PiFinder 구현은 `8133e494`, MF 장애 복구/스케줄 도구는 `90f15c5`에 반영했다. 후속 커밋은 결과 문서와 비교 지표를 추가한다. 운영 설치와 부팅 경로는 변경하지 않았다.

## 반영한 7개 항목

| 검토 사항 | 반영 결과 |
|---|---|
| NaN/무한대/잘못된 적위가 보정에 들어감 | 모든 솔빙 경로의 카메라·정렬 좌표 검증. 잘못된 보정 표본은 상태 변경 전에 거부. 극점을 벗어나는 보정 적용은 원래 RAW를 유지. 정렬 좌표 없는 표본이 이전 정렬 보정의 유효 기간을 연장하지 않음 |
| 완료 A, 대기 B, 새 C에서 B가 먼저 시작 | `LatestFrameWorker.exchange()`로 결과 회수와 새 제출을 묶어 C를 바로 실행. 실제 solver와 auto 재생 도구에 적용 |
| 오래된 비동기 결과/보정 유지 | 제출부터 큐·전처리·회수까지 5초를 넘긴 결과 제외. 결과 솔빙 후에도 다시 검사. 마지막 유효 보정 갱신부터 30초가 지나면 RAW로 복귀하고 2개 표본으로 다시 안정화 |
| MF 장애 때 매 프레임 재기동 | 실패 후 0.5→1→2→4→8초 재시도 대기. 대기 중 SEP 보조 사용. 정상 검출 응답 후 대기 상태 해제. 명시적 ctypes 비교 모드는 유지 |
| 여러 단계의 탐색 지연 누적 | RAW 단계에 3초 공유 예산, 별도 전처리 탐색 단계에 2.6초 공유 예산. 기존 개별 호출 제한도 유지. Tetra3 내부 해시/후보 반복과 반환 직전에서 만료·취소 검사 |
| 갱신 실패 시 소스/빌드 혼합 | 후보 체크아웃에서 MF 빌드·시험 후 활성화. 오류 시 이전 커밋·서브모듈·빌드 복원. 강제 종료 후 명시적 복원 지원. 시스템 패키지/OS 변경은 코드 업데이트에서 분리 |
| 실측 환경 식별 부족 | MF 커밋, 서버/.so 파일 SHA256, 실행 중 MF의 `/proc/PID/exe` SHA256, NumPy/SciPy/SEP/Pillow 버전, IPC/큐/보정/Tetra3 소스 해시 기록 |

전처리 계산 자체와 SQM/UI/IPC 전체에 대한 강제 시간 제한은 아니다. RAW가 실패하거나 정렬·보정 중일 때 전처리를 기다리는 복구 정책을 유지한다. 개별 NumPy/C 연산의 도중 강제 중단까지 보장하지 않는다.

코드 업데이트의 제한과 복원 절차는 PiFinder의 `docs/UPDATE_RECOVERY_ko.md`에 정리했다. 의존성 목록·OS 마이그레이션·OS 설정·서브모듈 구조 변경은 자동 반영 전에 중단하며 별도 설치 검증이 필요하다. 전원 차단 순간의 파일 시스템 전체 원자성이나 부팅 시 자동 복원은 제공하지 않는다. 이번 검증에서 실제 운영 업데이트를 실행하지 않았다.
