# 기본 구성 확정과 실측 비교 준비 — 작업 전 계획

기본은 검증된 MF4p(response/48개, SEP는 후보 5개 미만 또는 native 오류 때만),
전처리 scale worker 3개, auto scheduling이다. RAW 실패·정렬·보정 시 같은
프레임 전처리를 기다리는 기존 경로를 유지한다. 항상 비동기 anchor 방식은
흔들림 검증이 부족하므로 독립 비교기로 유지한다.

1. 검출기 프로필을 한 곳에서 정의하고 서비스 전환 스크립트와 같은 영상
   RAW/전처리 비교기가 공유한다. MF2, MF4p, 원본 정밀화, MF8p, SEP를 보존한다.
2. 실측 RAW 수집 → 캐시 → 동일 프레임 검출/솔빙 → anchor 비교 및 실제 실행
   지연 측정을 재현 가능한 명령으로 묶는다. RMSE, 성공률, 후보/매칭 수,
   지연 p50/p95, 프레임 출처를 보관한다.
3. 저장 경로에 선택 목표(J2000), 카메라/정렬 방향의 solve/estimate, 원래
   좌표 시각, snapshot 시각, 프레임 ID를 기록한다. 목표가 없으면 null이며
   실제 솔빙 위치로 목표를 만들어 채우지 않는다. 목표와의 거리는 지향 차이로
   해석하고 별 매칭 RMSE나 절대 오차와 혼동하지 않는다.
4. 운영 서비스와 부팅 설정은 그대로 두고 테스트 소스만 수정한다. 실제
   저장 경로·실패/빈 좌표·동일 ID 목표 이동·RA wrap을 테스트한다. 원본과
   실제 좌표는 로컬에 두고 코드·문서·집계만 승인된 두 테스트 브랜치에 푸시한다.

현재 장비는 마운트가 연결되지 않은 고정 상태이다. 실제 GOTO 응답/진동 및
절대 지향 정확도는 이번 준비 작업만으로 검증 완료라고 판단하지 않는다.
