# 다단계 ROI 구현과 개발 자료 결과

원본 복사 없이 stride를 유지한64×64 ROI에서2×2 검출을 다시 수행하고, 선택적으로32×32 ROI에서 원본 검출을 수행했다. ROI 시작점을 짝수로 맞춰2×2 bin 위상을 보존하고 전체 센서 좌표로 복원한다. 마지막 원본 단계는2×2 단계의 후보 순서를 유지한 채 좌표만 교체한다. 높은 해상도에서 확인되지 않은 후보는 버린다. 첫 단계의 최대128개 후보에서 최종48개까지 사용하며 새롭게 검출되지 않은 별을 억지로 보충하지 않는다.

개발30장에서는 모든 방식30/30 성공. 기존MF2 검출54.69ms, 4→2 ROI24.02ms, 4→2→1 ROI32.09ms. RMSE 중앙값25.57″/25.97″/24.77″. 8→2 ROI는10.30ms지만 매칭수 중앙값11.5개로 줄고 검출+솔브 p95가431.63ms로 증가했다(기존79.21ms). 개발 결과만으로 설정을 채택하지 않고 독립119장과 과거 구름102장으로 확인한다.

C++ 합성6/6: 새 검사는 홀수 크기513×385, stride padding, 경계 가까운 별, 비포화 핫픽셀, 원본좌표 및 invalid input을 포함한다. Python ABI/기존 좌표/신규 다단계 좌표12개 통과. Ruff 전체 검사/포맷371파일 통과. 기본 backend와 기존MF2 동작은 유지한다. 새 방식은 MF_DETECT_BINNING=4, MF_DETECT_PYRAMID=2 또는1로 명시 선택한다.
