# 토성 GoTo 후 추적 실측 — 2026-09-15

현재 장면의 재생 비교에서는 **RAW MF4p + 전처리 MF4p** 조합이 우선 후보다.
RAW는 빠르고 전처리는 별 위치의 적합 잔차를 줄였다. 실제 운영 추적은 마지막
60초의 기록 오차가 모두 허용치 3분각 이내였다. 다만 MF로 마운트를 제어한
시험은 아니며, 이동 중 전처리 보정 효과를 이번 자료만으로 확정하지 않는다.

[작업 전 계획](SATURN_GOTO_PLAN_ko.md)과
[수치 집계](SATURN_GOTO_AGGREGATE.json)를 함께 보관한다. 시각은 KST다.

## 기록 조건과 보존

- 기록을 시작했을 때 큰 GoTo 이동은 끝났고 OnStep 마운트가 토성을 추적 중이었다.
- 기존 운영 소스 `c1101d9f`, PiFinder PID 728 / Cedar PID 718을 유지했다.
  테스트 MF 서비스로 전환하거나 GoTo·Sync·guide 명령을 보내지 않았다.
- 21:32:47.998–21:34:47.469에 RAW TIFF **240장**, 약 120초를 기록했다.
  파일/픽셀 SHA256과 240개의 서로 다른 영상임을 확인했다.
- 21:35:11.848–21:38:11.804에는 RAW 출력을 끈 상태에서 추적 상태를
  약 0.25초 간격으로 **720회 / 180초** 추가 기록했다. MF 재생은 이 기록 후 실행했다.
- 노출은 기존 `auto_star` 약 245.6–250.9ms, gain은 `profile` 실제 약 29.51이었다.
  테스트에서 노출·gain을 바꾸지 않았다. RAW 기록 출력만 임시 활성화 후 복원했다.
- 원본 240장, 목표 좌표, 운영 로그, 상태·설정 스냅샷은 로컬에 보존했다.
  `target_XXX.json`은 가장 가까운 마운트 제어기 target 스냅샷과 연결했다.
  다운로드 시각과 target 스냅샷 간격은 p50 48ms / p95 100ms / 최대 125ms다.
  센서 노출과 원자적으로 묶인 좌표는 아니며, 좌표계는 앱이 제공한 그대로다.
  외부 토성 천문력과의 대조는 하지 않았다.

로컬 corpus는 `PiFinder_test_data/corpora/20260915_saturn_goto_live_recorded`,
로그·분석은 `PiFinder_test_data/work/saturn_goto`, 재생 결과는
`PiFinder_test_data/results/saturn_goto/mf_baseline`에 있다.
RAW 출력 비활성 상태에서 실패한 첫 시도는 영상이 없는 별도 디렉터리이며 집계에서 제외했다.

## 실제 운영 추적

아래 오차는 제어기가 선택한 정렬 관측 축 좌표와 제어기 목표 사이의 각거리다.
독립 측정한 토성 중심 위치 오차가 아니며, IMU 전파 좌표와 캐시된 상태도 포함한다.
720개 샘플은 시간 점유를 보여 주며 독립 솔빙 720회라는 뜻은 아니다.

| 구간 | 오차 중앙값 | p95 | 최대 | 허용치 3분각 이내 |
|---|---:|---:|---:|---:|
| 전체 추적 기록 180초 | 1.01분각 | 8.38분각 | 18.18분각 | 93.75% |
| 안정화 후 마지막 60초 | 1.25분각 | 1.51분각 | 1.65분각 | 100% |

21:35:35에 기존 제어기가 북/동 방향 2500ms guide pulse를 보냈다.
이후 솔빙 확인과 움직임 판정 전환 구간에서, 21:35:39.891에
`recovery waiting for solve anchor`가 기록됐다. 21:35:42.143의 최고
18.18분각은 **plate anchor를 바탕으로 IMU가 전파한 추정 좌표의 오차**다.
광학 관측으로 확인된 18분각 이탈이라고 해석하면 안 된다.
21:35:44.144에 기록 오차가 약 0.84분각으로 바뀌고, 21:35:45.144에
추적 보정이 enabled로 돌아왔다. 기록 종료 값은 약 1.34분각이었다.

제어기는 복구 GoTo에 필요한 새 광학 solve anchor를 기다렸다.
복구 횟수는 1→1, 수동 재지정 횟수는 2→2로 새 복구 GoTo는 없었다.
이 보호 동작은 유지해야 한다. 펄스와 추정 오차 증가가 시간상 이어졌지만,
이번 기록만으로 실제 마운트 이동·IMU 전파·상태 지연의 기여를 분리하지 못했다.
이 짧은 변동은 영상 수집 종료 이후여서 상태와 로그만 있고 해당 RAW는 없다.

운영 `pointing_coordinate_service.solved_sample()`은 plate anchor가 있으면
`aligned.estimate`를 읽고 IMU 전파 좌표도 반환한다. 따라서 상태의 `solved`라는
필드 이름만으로 순수 광학 좌표라고 판단하면 안 된다. 집계의 source 분류는
오차와 같은 guide 스냅샷을 사용했지만, 오차 자체의 캐시는 여전히 고려해야 한다.

새 RAW 기록 이전의 **과거 로그**에는 21:08:35–21:08:47에 controller 오차
23.09→2.87분각의 GoTo 완료와, 21:26:27–21:26:36에 15.91분각에서 시작한
복구 GoTo가 남아 있다. 이번 요청에서 초기 이동을 영상으로 기록한 결과는 아니다.

## 운영 솔빙 시간과 품질

| 관측 구간 | 로그의 전처리 경로 시도 | RAW 단계 p50 / p95 | 전처리까지 경과 p50 / p95 |
|---|---:|---:|---:|
| RAW 출력·영상 기록 중 | 67 | 99 / 162ms | 1643 / 1760ms |
| RAW 출력 종료 후 추적 | 117 | 74 / 119ms | 1427 / 1488ms |

두 구간은 시간·움직임·별 상태도 달라 기록 출력만의 비용 차이로 확정하지 않는다.
표의 전처리까지 경과는 운영 로그의 `through_preprocess`이며 센서 노출이나
마운트 동작까지 포함한 전체 응답시간이 아니다.

영상 기록 구간에서 중복을 제거해 관측된 성공 스냅샷은 55개였다.
전처리 Cedar center 52개, SEP center 3개이고 RMSE 중앙값 34.8초각 / p95
38.4초각, 매칭 별 중앙값 17개였다. 상태 샘플링이므로 55/72처럼 전체 시도에
대한 정확한 성공률로 해석하지 않는다.

후속 180초의 solver 상태는 중복 frame ID를 제거하면 125개, accepted 117개였다.
117개가 `raw_failed_same_frame_recovery`, 4개가 `confirming_raw_recovery`,
4개가 `moving`이고 모두 sync였다. RAW 실패·확인 중 전처리를 기다리는 기존
정책이 작동한 결과이며, 성공 RAW와 전처리가 비동기로 동작하는 경우를 입증하지 않는다.

## 같은 저장 영상의 MF 비교

마지막 RAW 32장을 연속 재생했다. 전처리는 5프레임 누적, scale worker 3개이며
첫 프레임은 누적 준비로 제외해 31개를 평가했다. MF4p와 MF2 모두 같은 RAW와
같은 전처리 결과를 사용했다. 이전 달·도심 수동 마스크는 적용하지 않았다.

| 경로 | 품질 통과 | RMSE 중앙값 | 검출+솔빙 p50 / p95 | 전처리 생성 포함 p50 / p95 |
|---|---:|---:|---:|---:|
| RAW MF4p | 31/32 | 53.5초각 | 75 / 237ms | 75 / 237ms |
| RAW MF2 | 31/32 | 52.7초각 | 107 / 247ms | 107 / 247ms |
| 전처리 MF4p | 31/31 | 27.7초각 | 43 / 63ms | 1316 / 1633ms |
| 전처리 MF2 | 31/31 | 27.7초각 | 98 / 129ms | 1364 / 1650ms |

전처리 생성 자체는 중앙값 1248ms / p95 1373ms였다. 두 RAW 모드가 같은
`raw_238`에서 실패했고, 같은 프레임의 전처리는 두 모드 모두 통과했다.
SEP fallback은 모든 재생 경로에서 0회였다. 이는 MF가 좌표를 검출했으나
솔빙에 실패한 경우까지 SEP로 다시 탐색했다는 뜻은 아니다.

**느린 꼬리도 남는다.** RAW MF4p의 검출+솔빙 최대는 2052ms, MF2는 2077ms였다.
전처리 MF4p는 생성 포함 최대 2219ms였다. 따라서 중앙값만 보고 모든 GoTo
업데이트가 75ms에 끝난다고 가정하면 안 된다. 이 진단 도구는 2600ms 검색
budget을 설정하므로 실제 운영 deadline과도 구분해야 한다.

RMSE는 매칭 별의 적합 잔차이고 절대 지향 정확도가 아니다. 운영 Cedar와는
검출기뿐 아니라 crop·채택 규칙·스케줄·관측 구간이 달라 직접적인 속도 배수나
정확도 우열을 계산하지 않는다. MF 재생은 카메라 축 솔빙이고, 실제 제어기의
정렬 관측 축 오차와 직접 비교하지 않았다.

또한 이번 재생은 0.5초 간격 저장 영상의 순차 비교다. 5프레임 창은 약 2초의
관측 이력을 사용하며 표는 노출·큐 대기·누적 이력 지연을 포함하지 않는다.
MF와 운영 서비스가 같은 장비를 사용한 상태의 시간이며 완전 격리 벤치마크가 아니다.

## 판단과 다음 검증 지점

1. 현재 장면은 MF4p RAW가 우선 후보다. MF2 대비 품질 통과 수가 같고 빠르다.
   이전 달·도심 장면의 MF2 우세를 모든 장면으로 일반화하지 않는다.
2. 전처리 MF4p는 품질 잔차와 단일 RAW 실패 복구에서 유리했다. RAW를 빠른
   변화 감지에 쓰고 안정된 전처리 좌표를 기준으로 삼는 기존 시험 방향을 지지한다.
   다만 이동 중 보정량의 정확성과 MF 실시간 GoTo 제어는 별도 실측이 필요하다.
3. RAW 실패·정렬·보정 중 전처리 대기, 복구 GoTo의 새 광학 앵커 요구를 유지한다.
   추후 성능 개선은 실패 검색의 최악 지연과 전처리 생성 비용을 함께 줄이는 데 집중한다.
4. 다음 실제 이동 기록에는 순수 `aligned.solve`의 좌표·관측 시각,
   `aligned.estimate`의 좌표·전파 시각, guide pulse 구간을 함께 남겨야 한다.
   현재 상태 필드의 의미를 먼저 구분하고 IMU 전파 오차를 실제 이탈로 취급하지 않는다.

`--conditions`로 실제 환경을 기록하도록 한 것이다. 미지정 시 조건 미제공으로
남긴다. 현재 corpus의 설명도 연결된 마운트의 토성 추적 상태로 바로잡았다.
검출·솔빙·마운트 제어 알고리즘과 기본 프로파일은 변경하지 않았다.

수집 CLI `--help`, 해당 파일 Ruff lint/format, Git diff 검사와 RAW 240장의
무결성·target sidecar 240개를 확인했다. 최종 설정 파일은 시작 스냅샷과 동일했고,
RAW 설정 전체가 복원됐다. 서비스 PID·운영 경로와 빈 systemd drop-in 상태를
확인했다. 원본 영상·좌표·장비 설정은 푸시하지 않고 문서·도구·집계만
승인된 두 저장소의 `test/cedar-free-20260915` 브랜치에 반영한다.
