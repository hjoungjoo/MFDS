# MF Detect Star 판매용 제품 사용 정책 검토

후속 구현: 사용자의 요청으로 테스트 기본 경로를 독립 native worker와 memfd로
전환했다. 아래 직접 연결/미구현 설명은 당시 검토 기록이다. ctypes는 명시적
비교 모드로 유지한다. [구현 프로토콜](../PROCESS_PROTOCOL.md)을 참고한다.
실제 라이선스 변경이나 결합 배포의 법률적 확정을 뜻하지 않는다.

2026-09-15. 사용자 요구와 후속 설계 기준을 기록한 문서다. **새 라이선스나
상용 허락의 발효 문서가 아니며**, 현재 LICENSE를 대체하지 않는다.

후속 확인: 사용자는 버전별 5년 FSL과 과거 MIT 코드의 존재를 수용할 수 있다고
설명했다. 기존 버전의 기한이 새 릴리스로 연장되는 것은 아니다.
[원본 PiFinder의 별도 상용 허락 및 서버 구조 확인](UPSTREAM_LICENSE_DISTRIBUTION_ko.md)을
후속 근거로 참고한다. 이 문서의 별도 문안 항목은 모든 판매 제품의 승인을
요구할 경우의 검토이며, 현재 FSL을 새 라이선스로 교체하기로 결정한 것이 아니다.

## 작업 전 기준

사용자 요구: MF Detect Star만 본인의 허락하에 판매용 제품에 사용하도록 한다.
PiFinder 소스를 수정한 나머지 부분은 원작자의 라이선스 조건을 그대로 따른다.
소스를 제공한다는 사실만으로 MF에 GPL 선택권을 추가하지 않는다.

이번 작업은 이 요구에 맞춰 기존 권장안을 수정하고 적용 범위·미해결 사항을
기록한다. 운영 서비스, 부팅 설정, 검출·솔빙 코드와 실제 라이선스 전문은 그대로다.

## 적용 범위

| 부분 | 유지할 원칙 |
|---|---|
| 독자 작성한 MF native 검출기 | 실제 권리자의 권한 범위에서 판매용 제품 사용을 별도 승인하는 조건 검토 |
| PiFinder 본체 및 이를 수정한 코드 | 원래 GPL 조건, 저작권 고지, 대응 소스 제공 의무 유지 |
| MF 저장소의 `integrations/pifinder/` | PiFinder에서 옮긴 GPL 코드이므로 MF 상용 제한을 덧붙이지 않음 |
| Tetra3/Cedar Solve, SEP 등 | 각 파일·의존성의 Apache/MIT/LGPL 등 기존 조건 유지 |
| 이미 MIT로 제공한 MF 사본 | 기존 MIT 권한 유지, 상용 사용 금지로 소급 변경하지 않음 |

저장소 하나에 모아 관리하는 것과 한 라이선스로 바꾸는 것은 다르다. 제한의
경계는 저장소 이름이 아니라 코드의 출처와 실제 권리다. Git 작성자나 기존의
`PiFinder contributors` 표기만으로 MF 전체의 단독 권리자를 확정하지 않는다.

## 현재 LICENSE와 요구의 차이

현재 `LicenseRef-Cedar-FSL-1.1-MIT-5year`는 Cedar Detect의 조건을 가져왔다.
이는 **Competing Use 제한**이며, 모든 판매 제품에 MF가 포함되면 예외 없이
사전 허락이 필요하다는 일반적인 문구는 아니다. 해당 버전 공개 후 **5년 뒤에는
MIT 허락**이 적용된다. 2026-09-15 공개분은 2031-09-15가 기준이다.
[Cedar 원문](https://github.com/smroid/cedar-detect/blob/2f403b8435259263f2a4fcd43f526918fe546d77/LICENSE.md).

따라서 현재 FSL을 그대로 두고 사용자 요구가 완전히 구현됐다고 표시하지 않는다.
모든 판매용 제품을 승인 대상으로 삼으려면 향후 버전에 적용할 별도 문안에서
다음을 확정해야 한다.

- 판매 제품에 포함·번들·사전 설치하거나 유료 기능으로 제공하는 행위의 범위.
- 무료 배포, 개인 사용, 연구, 기업 내부 사용, 재배포·수정본의 허용 범위.
- 승인권자, 서면 승인 방식, 승인받은 제품·버전·배포 범위.
- 5년 뒤 MIT 전환을 계속 둘지 여부. 전환 후에도 승인을 요구하는 조건으로
  설명해서는 안 되며, 이미 부여한 미래 허락을 새 문서로 없애려 하지 않는다.

이는 소스 열람이 가능한 제한적 라이선스와 별도 상용 계약을 구성하는 방향이다.
사용 분야를 제한하므로 일반적인 오픈소스 라이선스라고 표시하지 않는다.
현재 문서만으로 무료 사용 범위나 영구 제한을 새로 확정하지 않는다.

기존 MIT 커밋 `4763a01c1b23c5a0a60ddbfd208f5d18df89c2f6`과 점검한 현재
8개 native 파일은 SPDX 머리글을 제외하면 같다. 해당 MIT 사본을 적법하게
이용하는 업체의 상용 사용은 새 제한으로 막을 수 없다. 독자적인 향후 변경의
권리·범위와 과거 공개 코드의 권리는 분리해서 판단한다.
[검증 근거](LICENSE_AUDIT_ko.md).

## PiFinder와 연결하는 방향

현재 GPL Python 어댑터는 `ctypes.CDLL`로 MF를 같은 프로세스에 로드한다.
여기에 MF 판매 승인 조건만 추가하면 GPL 결합 배포 문제는 남는다. 소스 공개나
MF 권리자의 자기 제품 사용 허락만으로 제3자의 GPL 조건이 면제되지는 않는다.
GPL 선택권을 MF에 주는 대안도 수령자의 상업적 재배포를 허용하므로 선택하지 않는다.
[GPLv3 §5/§10](https://www.gnu.org/licenses/gpl).

우선 검토할 기술 방향은 MF를 **독립적으로 사용할 수 있는 검출 프로그램**으로
두고 PiFinder의 GPL 어댑터가 일반 이미지 입력과 별 좌표 출력 인터페이스를
사용하도록 하는 것이다. MF 내부로 GPL 전처리·상태 관리 코드를 옮기지 않는다.
PiFinder 없이 실행할 수 있는 CLI/서버, 다른 검출기로 교체할 수 있는 어댑터,
독립 빌드·배포와 단순한 데이터 교환을 설계 기준으로 삼는다.

프로세스·소켓 분리만으로 적법한 별개 저작물이 확정되는 것은 아니다.
전용 의존성과 복잡한 내부 자료구조 공유 등 실제 결합 정도를 검토해야 한다.
다른 경로는 영향을 받는 GPL 코드 권리자들에게 유효한 연결 예외를 받는 것이다.
MF 쪽에만 연결 허용 문구를 쓰는 것으로는 충분하지 않다.
[FSF 결합 판단](https://www.gnu.org/licenses/gpl-faq.en.html#MereAggregation),
[FSF 연결 예외](https://www.gnu.org/licenses/gpl-faq.en.html#GPLIncompatibleLibs).

독립 실행을 구현한다면 매 프레임 프로세스를 시작하지 않고 지속 실행하는
worker를 검토한다. 이미지·응답에는 frame ID와 시각을 포함하고 기존 RAW/병렬
전처리·동기 복구 순서는 유지한다. IPC의 복사 비용, 처리 시간 median/p95,
솔빙 성공률·좌표 오차·실패 복구를 같은 기록 데이터로 비교해야 한다.
아직 구현·실측하지 않았으므로 성능 유지나 GPL 분리 적합성을 보증하지 않는다.

## 작업 후 기록

기존 GPL 이중 라이선스 권장안을 철회하고 위 사용자 요구를 우선 기준으로 연결했다.
PiFinder 병합·배포 문서에도 MF를 GPL로 바꾸는 것이 선행 조건인 것처럼 보이지
않도록 반영한다. 현재 LICENSE/SPDX와 구현은 변경하지 않았다.
라이선스 문안 확정과 결합 구조 해결은 후속 작업이며, 현재 배포 적합성이
확인됐다는 뜻이 아니다. 문서 변경에는 경로·라이선스 범위 검사와 diff 검사를
적용하고, 검출 성능 재측정 결과로 표시하지 않는다.
