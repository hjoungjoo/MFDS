# 중앙 하단 달·도심 조명: 노출 실측과 달 소실 후 기록

## 결과와 권고

달이 보이던 기록에서 주 좌표의 가장 안정적인 후보는 **400 ms / gain 8 + 검출 전 지상·달 영역 제외 + MF4p 전처리 10프레임**이었다. 32장 재생 중 초기 1장을 제외한 31회가 품질 기준을 통과했고, 기존 정지 상태 연속성 검사까지 통과한 것은 29회였다. **200 ms / gain 15 + 전처리 5프레임**은 품질 30회·연속성 28회로 짧은 노출과 지연을 우선할 때의 유망한 대안이다.

추가로 **RAW MF2 + 하늘 영역 제외 + 전체 영역 우선 탐색**이 빠른 보조 경로 후보로 확인됐다. RAW MF4p가 놓친 별을 더 찾았으며 400 ms/gain 8에서 32/32회 품질 통과를 유지했다. 그러나 전체 우선 RAW의 연속성 통과는 21/32회로 전처리보다 낮았다. 빠른 RAW와 안정된 전처리 좌표를 병행하는 방향을 지지하며, 실제 흔들림 보정까지 검증한 것은 아니다.

운영 서비스/부팅 경로/기본값은 유지했다. 이번 결과는 저장 RAW의 MF 재생이며, 장면에 맞춘 수동 마스크를 포함한다. 시간 순서대로 노출을 변경했고 이후 달이 사라졌으므로, 차이를 노출·게인만의 인과 효과로 확정하지 않는다. 현재 기본 누적 5프레임을 일괄 10으로 바꿀 근거도 없다.

## 기록과 설정 복원

- 달이 보이던 세션: 2026-09-15 20:00:33~20:08:44 KST. 자동 노출 전후 각 40장과 수동 8조건 각 32장, 합계 **336장**.
- 사용자 달 소실 알림 이후 별도 촬영: **20:19:42~20:20:21 KST, 40장**. 총 376장이다. 이미지에서 달의 밝은 원형상이 보이지 않는 것을 확인했으며, 원인은 확인하지 않았다.
- TIFF 원본, 파일/픽셀 SHA256, 촬영 전후 실제 제어 값, 관측 상태/좌표 API 응답, 설정·실행 소스 정보와 조건별 인덱스를 로컬 보관했다. 독립적으로 지정된 타겟 좌표는 없으므로 null이다. CAM_FAILED의 과거 좌표를 현재 정답으로 쓰지 않는다.
- 수동 변경 시 실제 노출 ±5%, 실제 gain ±8% 안에서 서로 다른 센서 시퀀스 3개를 확인하고 3초 더 기다렸다. 저장 256장 모두 다운로드 전후 실제 제어 값이 해당 조건의 허용 오차 안에 있었다.
- 실제 gain은 요청 30→29.5121, 15→14.7911, 8→7.94328이었다. 25 ms의 실제 노출은 24.992 ms이며 나머지 수동 노출은 요청값과 같았다.
- 수동 실험 후 `auto_star` / gain `profile`을 복원했다. 설정 JSON 내용은 실험 전과 동일했고 PiFinder PID 719, Cedar PID 713 및 enabled/부팅 경로를 유지했다. 자동 제어의 이후 실제 노출·gain 변화는 허용된 원래 동작이다.
- 운영 소스는 PiFinder `c1101d9f`, 실험 출발 테스트 핀은 PiFinder `fb77f4f2` / MF `557af73`이다. 검출기·전처리 런타임은 변경하지 않았으며 이번 추가 소스는 기록/재생/집계 도구다.

현재 운영 TIFF에는 센서 ImageDescription이 없다. API 스냅샷은 TIFF와 원자적으로 연결되지 않는다. 또한 자료 통합 중 수동 실험 직전 제어 스냅샷 한 개가 초기 세션 스냅샷으로 덮어써져 `session_initial_controls.json`으로 명명하고 `session.json`에 한계를 기록했다. 원복 요청, 조건별 안정화 기록, RAW 및 다운로드 전후 제어 기록은 보존되어 있다.

## 노출 1차 비교

각 조건의 마지막 16장을 같은 MF4p 설정으로 재생했다. RAW는 16회, 전처리는 초기 1장 제외 15회다. 전처리 배경 계산은 workers=3, 누적은 5프레임이며 각 조건마다 초기화했다. SEP 단독 비교군은 쓰지 않고 기존 MF 실패/후보 부족 시 fallback만 허용했다.

아래 영역 제외는 TIFF 표시 회전을 되돌린 1080×1920 배열에서 x<500과 (616,548), 반경 160px를 제외한다. 경계 후보는 16px 더 피한다. 전처리 영상에는 전처리 후·별 검출 전에 적용한다. 다른 자세에 그대로 사용할 수 있는 자동 마스크가 아니다.

| 조건(요청값) | 하늘 포화 중앙값 | RAW+영역 제외 | 전처리 MF | 전처리 MF+영역 제외 |
|---|---:|---:|---:|---:|
| 자동, 변경 전 | 0.413% | 0/16 | 0/15 | 4/15 |
| 25 ms / 30 | 0.003% | 0/16 | 0/15 | 0/15 |
| 50 ms / 30 | 0.008% | 1/16 | 0/15 | 0/15 |
| 100 ms / 30 | 0.264% | 0/16 | 0/15 | 7/15 |
| 200 ms / 30 | 19.776% | 0/16 | 0/15 | 5/15 |
| 400 ms / 30 | 68.689% | 0/16 | 0/15 | 0/15 |
| 200 ms / 15 | 0.218% | 0/16 | 0/15 | 14/15 |
| 400 ms / 8 | 0.433% | 0/16 | 8/15 | 15/15 |
| 100 ms / 30 재측정 | 0.248% | 0/16 | 0/15 | 9/15 |
| 자동, 복원 후 | 0.790% | 0/16 | 0/15 | 9/15 |

영역 제외 없는 RAW MF는 모든 조건에서 0/16이었다. gain 30의 400 ms는 하늘 영역 약 68.69%가 포화되어 실패했다. 400 ms/gain 8은 약 0.433%였다. 같은 100 ms 재측정이 7/15→9/15로 달라졌으므로 하늘 변화 영향이 존재한다. 이 반복만으로 다른 노출 조건의 시간 영향을 완전히 보정할 수는 없다.

## 같은 연속 32장: 누적 길이와 안정성

조건별 동일한 32장에 누적 5/10을 적용했다. 초기 1장을 제외한 31회의 결과이며, 서로 겹치는 누적 창을 독립적인 31개 실험으로 해석하지 않는다. 연속성은 촬영 시각과 기존 SolveContinuityGate(stationary=True, prefer_preprocessed=True)로 검사했다. 최초 확인 대기 등으로 품질 통과보다 발행 가능한 결과 수가 적다.

| 조건 | 누적 | 품질 통과 | 연속성 통과 | 매칭 별 중앙값 | RMSE 중앙값 | 처리 p50 / p95 |
|---|---:|---:|---:|---:|---:|---:|
| 100 ms / 30 재측정 | 5 | 22/31 | 19/31 | 8 | 104.4″ | 1.429 / 1.714초 |
| 100 ms / 30 재측정 | 10 | 28/31 | 24/31 | 9 | 85.9″ | 1.512 / 2.069초 |
| 200 ms / 15 | 5 | 30/31 | 28/31 | 11 | 92.2″ | 1.382 / 1.696초 |
| 200 ms / 15 | 10 | 30/31 | 26/31 | 15 | 103.8″ | 1.607 / 2.172초 |
| 400 ms / 8 | 5 | 31/31 | 27/31 | 8 | 87.8″ | 1.383 / 1.945초 |
| 400 ms / 8 | 10 | 31/31 | 29/31 | 13 | 91.5″ | 1.487 / 1.910초 |

처리 시간은 전처리+검출+Tetra 탐색의 **직렬 합계**다. 센서 노출, 대기열, 누적 이력의 나이, 비동기 결과 발행까지의 실제 지연을 뜻하지 않는다. 운영 서비스가 동작하는 같은 장비에서 추가 비교 작업끼리는 순차 실행했다. 마운트가 없으므로 GoTo/빠른 흔들림 보정 성능은 검증하지 않았다.

400 ms/gain 8에서 영역 제외 없이 전처리하면 누적 5는 13/31, 누적 10은 7/31에 그쳤다. 지상 조명도 누적 강화되기 때문에 누적 길이만 늘리는 것은 충분하지 않다. 반면 영역 제외를 적용하면 둘 다 31/31이다. 200 ms/gain 15에서는 누적 10이 품질 통과를 늘리지 못하고 연속성·지연·RMSE도 불리했다. RMSE는 매칭 잔차이며 독립적인 절대 지향 정확도가 아니다.

운영 솔버의 유효 `camera_center`와 MF 중심을 비교한 17개 스냅샷(운영 성공 시각 11개)에서 중심 간 거리 중앙값/p95는 누적 5일 때 51.5/121.6각초, 누적 10일 때 63.5/105.2각초였다. 이는 같은 하늘 영역이라는 보조 확인이다. 보정된 관측 지향 RA/Dec와 카메라 중심을 혼동하지 않았으며, API 비동기·누적 차이·공통 Tetra DB 때문에 독립 정답 검증은 아니다.

## 달이 보이지 않는 후속 자료

기존 336장과 별도 조건이다. 원래 자동 제어는 gain을 29.51→14.79→29.51로 잠시 시험했고 노출은 108.459~216.414 ms였다. 비교에는 제어 값이 안정된 마지막 15장(118.414 ms/gain 29.5121)을 사용했다. 달 원형 마스크는 끄고 지상 영역(x<500, 경계 여유 16px)만 제외했다.

| 방법 | 품질 통과 | 연속성 통과 |
|---|---:|---:|
| RAW MF | 0/15 | 0/15 |
| RAW MF + 지상 제외 | 1/15 | 0/15 |
| 전처리 5 MF | 0/14 | 0/14 |
| 전처리 5 MF + 지상 제외 | 11/14 | 10/14 |
| 전처리 10 MF + 지상 제외 | 12/14 | 11/14 |

이 후속 자료는 달 소실 자체의 효과를 분리한 대조 실험이 아니다. 촬영 시각과 자동 제어도 함께 달라졌다.

## RAW 해상도 보조 점검

- 400 ms / 8에서 같은 마지막 16장에 MF2/영역 제외를 적용: 품질 16/16, 검출 p50 112.0 ms.
- 200 ms / 15에서 같은 마지막 16장에 MF2/영역 제외를 적용: 품질 15/16, 검출 p50 98.6 ms.


연속 32장 전체에서도 확인했다. 아래 시간은 기존 중앙→전체 탐색 순서의 검출+탐색(전처리 행은 전처리 포함)이다.

| 조건 | 경로 | 품질 통과 | 연속성 통과 | RMSE 중앙값 | 처리 p50 / p95 |
|---|---|---:|---:|---:|---:|
| 200 ms / 15 | raw MF2+영역 제외 | 29/32 | 17/32 | 98.7″ | 0.411 / 1.118초 |
| 200 ms / 15 | pre MF2+영역 제외 | 30/31 | 28/31 | 92.2″ | 1.479 / 1.813초 |
| 400 ms / 8 | raw MF2+영역 제외 | 32/32 | 18/32 | 94.7″ | 0.548 / 1.196초 |
| 400 ms / 8 | pre MF2+영역 제외 | 31/31 | 27/31 | 87.8″ | 1.464 / 2.123초 |

MF2 RAW의 SEP fallback 호출은 두 조건 모두 0회였다. 전처리 MF2는 MF4p 전처리와 품질 통과 수가 같으며 더 빠르지 않았다. 이 장면에서는 RAW에 추가 해상도가 유효하고, 전처리에는 MF4p를 유지하는 조합이 유망하다.

같은 RAW MF2 별 좌표를 고정하고 탐색 순서만 전체→중앙으로 바꿨다. 이 비교 시간은 **별 검출·노출·전처리를 제외한 탐색만**이다.

| 조건 | 품질 통과 전/후 | 전체 우선 연속성 | 탐색 p50 전→후 | 탐색 p95 전→후 |
|---|---:|---:|---:|---:|
| 200 ms / 15 | 29/32 → 29/32 | 17/32 | 304.6 → 36.0 ms | 1013.5 → 570.7 ms |
| 400 ms / 8 | 32/32 → 32/32 | 21/32 | 441.3 → 30.7 ms | 1086.6 → 182.7 ms |

두 실행 모두 기존 성공을 잃지 않았으며, 400 ms 조건의 전체 우선 탐색 중앙값은 반복에서 약 31~44 ms였다. 이 결과를 카메라 입력부터 좌표 발행까지의 전체 지연으로 해석하면 안 된다. 적용 후보는 신뢰할 수 있는 하늘 마스크가 있는 이 장면의 경로이며, 일반 장면의 중앙 우선 정책을 전역 변경하지 않았다.

RAW MF2는 품질 기준을 통과해도 중심 좌표 변화가 전처리보다 크다. RAW 글로벌 솔빙 좌표의 변화를 그대로 실제 흔들림으로 간주할 수 없으며, 같은 별의 영상 변위와 IMU 일치 여부를 함께 검증해야 한다. 사용자 요청의 RAW 움직임 보조/안정된 전처리 주 좌표 구조가 타당한 후보지만, 마운트 미연결 상태로 실제 GoTo 검증은 남아 있다.

## 검증·재현·보관

노출 기록기의 캡처 timeout/중단 시 원복 테스트 2개를 통과했다. 추가 도구는 Ruff 검사 및 기록 영상 실행을 확인했고, 집계의 시도/성공 수가 개별 재생 결과와 일치함을 확인했다. RAW 376장의 파일 해시와 픽셀 중복 여부를 검증했다. 런타임 변경이 없어 이전 전체 단위 테스트를 이번 신규 실행 결과로 인용하지 않는다.

기록 도구는 `integrations/pifinder/scripts/capture_exposure_sweep.py`, 분석 도구는 `diagnose_moon_city.py`, 연속성/시간 집계는 `summarize_scene_replays.py`다. 다음은 PiFinder 테스트 checkout의 python 디렉터리에서 실행한다.

```sh
# 같은 corpus에 누적 창만 5/10으로 바꾸어 별도 출력 디렉터리에 재생
PIFINDER_DATA_DIR=/home/pifinder/PiFinder_test_data PYTHONPATH=.:scripts \
python mf_detect_star/integrations/pifinder/scripts/diagnose_moon_city.py \
  CORPUS NEW_OUTPUT --config CAPTURE_CONFIG.json --frames 32 --tail \
  --temporal 10 --sources pre --modes mf4p,mf4p_mask \
  --city-x 500 --moon-x 616 --moon-y 548 --moon-radius 160 --no-save-pre

# 달이 보이지 않는 자료: --moon-radius 0, --frames 15 --tail
# RAW MF2 보조 비교: --sources raw --modes mf2_mask
PYTHONPATH=. python mf_detect_star/integrations/pifinder/scripts/summarize_scene_replays.py RESULTS_ROOT

# RAW MF2의 같은 별 좌표로 전체→중앙 탐색 비교 (개별 좌표 출력은 로컬 보관)
PYTHONPATH=.:scripts python mf_detect_star/integrations/pifinder/scripts/compare_scene_solve_order.py \
  MF2_REPLAY_OUTPUT --output NEW_ORDER_OUTPUT
```

로컬 보관은 `PiFinder_test_data/corpora/20260915_moon_lower_exposure/session.json`에서 전후 자동 촬영과 8조건을 찾을 수 있다. 달 소실 후 자료는 `corpora/20260915_moon_not_visible_auto/`이다. 결과는 `results/moon_lower_exposure/`, 로그·설정·시각화는 `work/moon_city_lower/`에 있다. 원본/좌표/장비 설정은 푸시하지 않고 코드·문서·[집계 JSON](moon_lower_exposure.summary.json)만 공유한다.
