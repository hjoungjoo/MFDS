# 메인 채택 결정과 검증 계획 — 2026-09-15

사용자가 전체 실측 결과를 종합한 기본 구성의 메인 병합과 최종 서비스 전환을
요청했다. 일반 관측의 기본은 MF4p RAW + 같은 MF4p 전처리로 확정한다.

| 항목 | 확정 구성 |
|---|---|
| 검출 | 전체 1/4 탐색 → 후보 주변 1/2 정밀화, sigma 4.5, 최대 48개 |
| 전처리 | CFA 보존, 배경 scale 3작업자, 시간 누적 5장 |
| 실행 | 별도 native 프로세스 + memfd, 호출 스레드별 worker 재사용 |
| 스케줄 | auto: 안정 RAW + 비동기 전처리 bias, 실패·초기화·정렬·보정은 동기 복구 |
| SEP | MF 오류 또는 필터 후 후보 5개 미만에만 보조 |
| 솔빙 | 개선 Tetra3 검색, 기존 품질·연속성·시간 예산 유지 |

[현재 기본값](test_cedar_free_20260915/CURRENT_DEFAULTS_ko.md),
[통합 실측](test_cedar_free_20260915/INTEGRATED_OPTIMIZATION_RESULTS_ko.md),
[토성 실측](test_cedar_free_20260915/SATURN_GOTO_RESULTS_ko.md)을 근거로 한다.
토성 저장 영상에서 RAW MF4p는 31/32, 전처리 MF4p는 31/31 통과했고
검출+솔빙 중앙값은 각각 75ms / 43ms였다. 전처리 생성 포함 중앙값은 1316ms다.
RAW 실패 검색 최대 2052ms와 관측/재생 조건 차이를 함께 고려한다.

MF2, sync, ctypes, 전처리 anchor, 수동 영역 제외와 긴 누적은 비교 옵션으로
남긴다. 달·도심 특정 장면의 최상 결과를 일반 기본값으로 적용하지 않는다.
전처리 anchor 실험은 카메라 축에 한정되며 정렬 축·GoTo에 연결되지 않았으므로
기존 auto bias 방식을 유지한다. RMSE는 별 적합 잔차이고 절대 지향 오차가 아니다.

## 병합 전 계획

1. 최신 main에서 테스트 브랜치를 이력 보존 병합한다. 운영 checkout과 분리해 검증한다.
2. native 빌드/합성 회귀, 라이선스 고지·정본 배치 검사, PiFinder 단위·smoke,
   lint/format/type 검사와 Cedar 없는 설치·갱신 검사를 수행한다.
3. MF main을 먼저 푸시하고 PiFinder가 그 커밋을 고정하도록 병합한다.
4. 사용자 후속 요청에 따라 운영 main을 갱신하고 Cedar 서비스를 해제한 후
   MF 서비스의 기동·솔빙·좌표 발행을 확인한다. 원본 로그와 설정은 로컬 보존한다.
5. 검증 결과와 최종 서비스 상태를 PiFinder 배포 기록에 남긴다.

기존 라이선스와 출처 고지를 유지한다. 코드 병합·서비스 검증이 판매 이미지의
법률 검토나 냉부팅 검사를 대신하지 않는다.

## MF 병합 검증

새 main 작업 디렉터리에서 native 전체 빌드와 합성 회귀 6/6을 통과했다.
라이선스 원문 해시·23개 정본 통합 파일 배치 검사, 통합/도구 Python lint와
35개 파일 format 검사 및 Git diff 검사를 통과했다. 기존 검증된 native
알고리즘을 그대로 병합했으며 이번 확정 작업에서 검출 임계값을 바꾸지 않았다.
