# 다음 가속 개선 판단 — 2026-09-23

이 문서는 구현 전 판단 기록이다. 이후 적용된 공통 NEON 경로와 최종 옵션·검증은
[CPU 누적 최적화](CPU_PREPROCESS_ko.md)에 정리했으며 v0.4.0에 포함된다.

**다음 정식 개선은 CPU NEON으로 시간 누적 연산을 통합하는 것을 우선한다.**
소규모 실제 영상 A/B에서 전체 전처리 중앙값이 4.9~10.9% 감소했고,
32쌍의 출력 영상·evidence·진단값이 모두 정확히 같았다. GPU 타일은 기존
GPU보다 빨라졌지만 CPU보다 여전히 느려 후속 실험 후보로 유지한다.

GPU 구간을 분리 측정하고 GPU 공유 메모리 타일과 CPU NEON 누적을 별도
작업 디렉터리에서 시험했다. 전처리 운영 코드와 기본 옵션은 이번 조사에서
변경하지 않았다. [이전 GPU 옵션 실측](GPU_PREPROCESS_RESULTS_20260923_ko.md)에
이어, 어느 개선부터 구현할지 결정하기 위한 실험이다.

## GPU 병목: 필터 실행 완료 구간이 약 91~92%

현재 V3D/Mesa는 `GL_EXT_disjoint_timer_query`를 제공하지 않는다. 각 단계 뒤에
`glFinish()`를 넣은 별도 라이브러리로 완료까지의 벽시계 시간을 측정했다.
필터 시간에는 GPU 실행 외에 드라이버·스케줄링·대기가 포함되므로 순수 장치
실행 시간이라고 표현하지 않는다. 추가 동기화가 흐름을 바꾸므로 동일 실험
라이브러리에서 계측을 끈 정상 실행도 교대 측정했다.

고정 검증과 달·도심 `raw_005.tiff`에서 실제 전처리 잔차를 각각 준비했다.
잔차 크기는 1920×1080 배열이며 각 입력을 14회 반복, 첫 2회 제외 12회씩 집계했다.
아래는 ms 중앙값이다. 각 구간 중앙값의 합은 전체 중앙값과 반드시 같지 않다.

| 구간 | 고정 검증 | 달·도심 |
|---|---:|---:|
| 입력 업로드 완료 | 4.5 | 2.9 |
| 세로 필터 완료 | 121.8 | 122.7 |
| 가로 필터 완료 | 122.2 | 121.8 |
| 완료 후 결과 매핑 | 0.06 | 0.08 |
| 결과 CPU 복사 | 14.8 | 16.7 |
| 계측 포함 전체 호출 | 265.8 | 265.5 |
| 추가 동기화 없는 GPU 호출 | 269.3 | 271.9 |
| 같은 입력 CPU 호출 | 183.4 | 186.7 |

평균 시간으로 계산하면 필터 완료 구간이 전체의 **91.8% / 91.3%**, 입출력
복사는 **7.9% / 8.4%**다. 입력·출력 복사를 모두 없앤다고 가정해도 현재 필터
완료 구간 약 245ms가 CPU 전체 호출보다 길다. 따라서 **zero-copy나 비동기
전송을 첫 개선으로 선택하지 않는다.** 이는 현재 DoG 부분 이식의 판단이며,
여러 단계를 GPU에 묶는 다른 설계 전체를 부정하는 결과는 아니다.

계측 중 `get_throttled=0x0`, 온도 시작/종료 64.8/64.2°C, 관측한 V3D 클럭은
약 960MHz였다. 클럭·전압·서비스 설정은 변경하지 않았다. 지속적인 온도·클럭
추적이나 다른 서비스 부하 통제는 하지 않았다.

## GPU 공유 메모리 타일 시험

작업 그룹이 halo를 포함한 주변 픽셀을 shared memory에 함께 읽고 재사용하도록
셰이더만 바꾼 시험 라이브러리를 만들었다. CFA별 반사 경계, 필터 계수와 연산
순서를 유지한다. 현재→타일 / 타일→현재 순서의 두 라운드, 입력별 각 8회 중
첫 2회 제외하여 방식·장면별 12회다. 복사와 결과 회수를 포함한 호출 시간이다.

| 장면 | 현재 GPU | 타일 GPU | GPU 대비 감소 | 타일 비교 실행의 CPU |
|---|---:|---:|---:|---:|
| 고정 검증 | 273.6ms | 229.1ms | 16.2% | 179.9ms |
| 달·도심 | 279.0ms | 222.6ms | 20.2% | 160.4ms |

타일 커널은 유효한 GPU 개선이지만 CPU보다 여전히 49~62ms 느리다. 이 한 가지를
적용해서 기본 GPU 모드로 전환할 근거는 없다. 시험 커널로 실제 V3D 테스트
32개를 통과했고 실제 잔차의 CPU 대비 최대 응답 차이는 0.0009765625 ADU였다.
이 비교는 두 저장 프레임의 잔차 필터와 합성 회귀이며, 전체 실제 시간 누적
corpus의 GPU 품질·솔빙 검증을 대신하지 않는다.

## 전체 CPU 전처리에서 개선 여지가 큰 구간

각 장면 RAW 10장을 순차 처리하고 첫 4장 제외 6장을 집계했다. 배경 worker는
3개, 누적 창은 5장이다. 다음은 상세 계측 실행의 ms 중앙값 범위다.

| 구간 | 중앙값 범위 |
|---|---:|
| 세 배경 scale 완료 대기 | 373~411ms |
| 배경 결합·포화 마스크·분위수·가중치 등 | 270~271ms |
| CPU DoG | 178~183ms |
| float16→float32 왕복 양자화 | 57~65ms |
| 새 프레임 가중치·단일 프레임 후보 마스크 | 63~64ms |
| 5프레임 신호/evidence/지속 횟수/마스크 합산 | 125~126ms |
| 반복 후보 성분 판별과 마스크 dilation | 121~127ms |
| 출력 변환 | 27~29ms |

배경 worker들은 병렬이므로 worker 시간을 합산해 전체 절감 가능 시간으로
계산하지 않는다. 가장 늦게 끝나는 local scale 안의 보간만 185~192ms였다.
배경 보간 전용 구현도 다음 후보지만, SciPy의 좌표·반사·반올림 규칙을 그대로
유지하는 검증이 필요하다. 이 조사는 구간을 좁혔으며 개별 median/percentile/
연결 성분 알고리즘의 최적 구현을 모두 비교하지는 않았다.

## NEON 누적 시험과 구현 우선순위

현재 Python/NumPy는 각 보관 프레임마다 전체 영상의 신호 합, evidence 합,
지속 횟수와 마스크 OR를 별개로 갱신한다. 시험 C++ 구현은 한 번에 4픽셀씩
NEON 레지스터에 누적하고 마지막에 결과를 저장한다. 프레임별 부동소수점
덧셈 순서와 임계값의 `>=` 비교, 기존 float16 양자화를 유지한다. 빠른 수학
옵션이나 누적 창 길이 변경은 적용하지 않았다.

각 장면 8장×2회, CPU/NEON 순서를 프레임·반복별로 교대했다. 각 반복 첫 4장을
시간 집계에서 제외해 장면·방식별 8회, 정확도는 준비 프레임까지 총 32쌍이다.
배경 worker 3개, 누적 5장, CPU DoG를 공통으로 사용한다.

전체 전처리 ms 중앙값 / p95:

| 장면 | 기존 CPU | NEON 누적 | 중앙값 감소 |
|---|---:|---:|---:|
| 고정 검증 | 1238.9 / 1286.0 | 1178.1 / 1245.9 | 4.9% |
| 달·도심 | 1283.2 / 1385.8 | 1143.9 / 1303.7 | 10.9% |

- 실제 영상 32쌍: 출력 픽셀, evidence 배열과 모든 반환 진단값이 정확히 같다.
- 작은 배열과 SIMD 끝부분, 1~5장 창, 임계값과 같은 값의 비교 등 25개 경계
  조합에서 NumPy와 신호/evidence 합·지속 횟수·마스크 OR가 정확히 같다.
- 새 누적 호출 자체는 실제 pipeline에서 중앙값 35~46ms였다. 앞의 상세 계측
  실행과는 별도 실행이므로 125ms에서 단순 차감해 전체 개선율을 계산하지 않는다.
  위의 전체 A/B 수치가 판단 근거다.
- 시험 구현은 1~5장이고 미리 capped evidence를 보관하는 현재 기본 경로에만
  적용했다. 나머지 설정은 기존 NumPy 루프를 유지한다.

권장 순서는 다음과 같다.

1. **NEON 누적 통합을 정식 옵션으로 구현:** GPL 통합 범위에 두고 ARM64 빌드,
   라이브러리 미설치·미지원 환경의 CPU 복귀, 특수 설정의 기존 경로를 유지한다.
   더 큰 corpus에서 동일성·솔빙 회귀와 RAW foreground 동시 부하의 p95를
   검증한 뒤 기본 사용 여부를 결정한다. 이번 시험 코드를 운영 경로에
   바로 연결하지 않았다.
2. **배경 보간 전용 CPU 구현 검토:** critical path의 local 배경/noise 보간
   185~192ms가 대상이다. worker 3개에서 이미 병렬 처리 중인 시간을 단순
   합산하지 말고 전체 대기 시간이 줄어드는지 본다. 좌표·반사·반올림을 보존한다.
3. **GPU는 타일 이후 커널 개선을 제한된 실험으로 유지:** 남은 49~62ms의
   CPU 대비 차이를 줄여야 한다. 여기에 여러 단계의 GPU 연속 처리를 검토하되,
   전체 전처리 이식이나 zero-copy부터 큰 변경을 시작할 근거는 아직 부족하다.

NEON 전체 개선율은 소규모 반복 관측값이며 다른 장면·서비스 부하에서 같은
비율을 보장하지 않는다. 이번 목표는 다음 구현의 우선순위 판단이다.

## 재현 자료와 범위

원본 영상은 수정하지 않았다. 실험용 코드·라이브러리·입력 해시·측정 JSON은
`/home/pifinder/PiFinder_test_data/work/gpu_profile_20260923/`에 보관했다.

- `prepare_profile.py`, `profile_gpu.py`, `gpu_profile.json`: GPU 단계별 완료 시간.
- `profile_cpu.py`, `profile_cpu_detail.py`, `cpu_profile_detail.json`: CPU 단계와 worker 보간 시간.
- `prepare_tiled.py`, `compare_tiled.py`, `tiled_comparison.json`: GPU 타일 시험.
- `reduce_neon.cpp`, `compare_neon.py`, `neon_comparison.json`: NEON 누적 시험.
- `provenance.json`: 원본 GPU 소스와 실험 코드·바이너리 SHA256.

모든 성능 값은 이 장비의 소규모 오프라인 실험이다. 카메라 노출, UI, 실제
RAW foreground 경합, 마운트와 솔빙 성공률은 측정하지 않았다. A/B는 같은
실행에서 비교하고, 서로 다른 계측 실행의 절대 시간을 빼서 개선율을 만들지 않는다.

완료 대기와 장치 타이머의 차이는
[Khronos EXT_disjoint_timer_query](https://registry.khronos.org/OpenGL/extensions/EXT/EXT_disjoint_timer_query.txt)
명세의 설명을 따른다.
