# 검토 후 개선 계획

기준: MF `3e7f045`, PiFinder `c7d9e0b4`. 테스트 브랜치에서 구현·검증하며 운영 서비스, 부팅 설정, 장비 설정은 변경하지 않는다.

1. 좌표의 유한성·적위 범위와 보정 적용 결과를 검증한다. 잘못된 카메라/정렬 좌표로 보정 상태를 변경하지 않는다.
2. 완료 결과 회수와 최신 프레임 제출을 하나의 연산으로 묶어 오래된 대기 프레임의 선행 실행을 막는다.
3. 비동기 결과는 제출 후 5초, 학습한 보정은 마지막 유효 표본 후 30초를 기본 만료 기준으로 삼는다. 만료 시 RAW로 복귀하고 새 표본으로 다시 안정화한다. RAW 실패·정렬·보정의 동기 복구 정책은 유지한다.
4. MF 반복 장애에 재시도 대기 시간을 적용하고 대기 중 SEP 보조 검출을 허용한다. 정상 응답 후 장애 상태를 해제한다.
5. 탐색 단계들이 공유하는 시간 예산과 Tetra3 내부 반복문의 취소/만료 검사를 추가한다. 전처리 복구에는 별도 예산을 보장한다. 단일 수치 연산의 실행 시간까지 강제로 제한하는 방식은 아니다.
6. 업데이트 후보를 별도 위치에서 준비·검증한 후 반영하고 실패 시 소스/검출기 빌드를 복원한다. 시스템 패키지와 OS 마이그레이션은 Git 복원으로 되돌릴 수 없는 경계를 명시한다. 실제 설치 갱신 대신 임시 저장소에서 실패 경로를 검증한다.
7. 기록에 MF 커밋, 실제 실행 파일 식별값, 관련 Python 소스 해시, 의존성 버전을 추가한다. 원본 영상·실제 관측 좌표·설정은 로컬에 둔다.

회귀 테스트, 전체 단위 테스트, 정적 검사와 기존 영상 재생으로 검증한다. 단계별 커밋/푸시 후 결과 문서에 수치와 한계를 기록한다.
