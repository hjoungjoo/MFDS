# 작은 별의 coarse 후보 탈락 수정

8 mm 렌즈 테스트에서 작은 별 표시 누락이 보고되어 확인했다. 해당 촬영의
원본 RAW는 로컬에 없어 첨부 화면의 개별 별에 대한 원인 확정은 하지 않았다.
소스 기준점은 MFDS `12304cc`, MFNavis `33dcbefd`다.

## 원인과 변경

4×4 축소 후 한 픽셀 또는 얇은 두 픽셀에 모인 별은 초기 후보의 최소 FWHM
0.55 및 최대 eccentricity 0.94 검사에서 제외될 수 있다. 기존 coarse 단계가
support 1픽셀을 허용하면서도 같은 상황의 모멘트 검사는 허용하지 않았다.
배경 500 ADU, 진폭 1500 ADU, sigma 0.85 센서 픽셀인 합성 별로 재현했다.

`detect_pyramid`의 4× 이상 초기 후보에만 최소 FWHM 0, 최대 eccentricity 1을
적용한다. 전체 4×4 탐색 → 기존 64×64 ROI의 2×2 정밀화는 그대로다.
검출 sigma, PSF 커널, noise floor, ROI 수 상한, 최종 2× 모양·support 검사,
솔버 최대 48개 입력은 바꾸지 않는다. 새 전체 영상 탐색은 추가하지 않는다.

MFDS Python 어댑터가 무시하던 `overlay_max_stars`도 반영한다. 이미 검출하고
품질 필터를 통과한 최대 128개 중 표시용 좌표를 별도로 반환하며, 솔버 입력은
48개로 유지한다. MFNavis RAW 경로도 이 표시용 좌표를 요청하고 사용한다.
전처리 경로에는 요청·사용 코드가 이미 있었다.

## 검증

- 추가 회귀 테스트는 수정 전 native 객체에서 실패하고 수정 후 통과했다.
  4× 셀 내 8개 위치와 두 pyramid 모드에서 작은 별을 유지하고 별도로 삽입한
  비포화 핫픽셀을 제거하는지 검사한다.
- `make -j2 all test`: native 8/8, temporal reduction 35개 창 통과.
- 수정 MFDS를 사용한 Python 검출·process 전송·MFNavis overlay·비상 SEP 관련
  테스트 98개 통과. 기존 고정 MFDS 패키지와의 MFNavis 호환 테스트 46개 통과.
- 변경 Python 파일 Ruff lint/format 및 두 저장소 `git diff --check` 통과.

기존 6 mm RAW 40장에 구·신 ctypes 바이너리를 번갈아 적용했다. 입력마다
첫 측정을 제외하고 각각 3회 측정했으며, binning=4, sigma=4.5, pyramid=2,
capacity=128, 포화값=4095를 동일하게 사용했다. 광해 30장과 달/건물 10장이다.

| 지표 | 수정 전 | 수정 후 |
|---|---:|---:|
| 프레임별 검출 시간 중앙값의 중앙값 | 44.12 ms | 42.56 ms |
| native 후보 수 합계 | 1,936 | 1,948 |
| 기존 후보 유지(1 센서 픽셀 이내) | — | 1,936/1,936 |

이 측정에서 속도 저하는 관찰되지 않았다. 시간 차이는 속도 개선의 증거로
해석하지 않는다. 추가 12개는 검출 후보이며 카탈로그로 확인한 별 수가 아니다.
새 후보가 생기는 장면에서는 기존 ROI 검사 횟수가 늘 수 있다. 실제 8 mm
촬영의 누락률과 솔빙 성공률은 해당 RAW로 추가 확인해야 한다.

재현 스크립트와 프레임별 결과는 로컬
`/home/pifinder/PiFinder_test_data/results/compact_stars_20260924/`에 보관했다.
`compare.py OLD_SO NEW_SO`를 MFNavis 가상환경 및 `PYTHONPATH=MFNavis/python`으로
실행하면 동일 자료를 비교한다.

## 적용 상태

이 수정은 MFDS v0.4.1에 포함된다. MFNavis는 해당 릴리즈의 플랫폼별
아카이브·manifest 해시와 소스 커밋을 lock에 고정하고 패키지를 갱신한다.
기존 설치의 실행 중 프로세스에는 패키지 파일 교체만으로 반영되지 않으며,
업데이트 이후 다음 서비스 시작부터 새 바이너리를 사용한다.
