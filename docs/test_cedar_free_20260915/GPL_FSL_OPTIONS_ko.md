# MF FSL / PiFinder GPL 배포 선택안

후속 구현: 테스트 기본 경로는 이제 독립 native worker와 memfd 이미지 전달이다.
아래 ctypes 설명은 검토 당시 구조이며 명시적 비교 모드로 남아 있다.
[구현 프로토콜](../PROCESS_PROTOCOL.md). 이 변경만으로 법적 적합성을 확정하지 않는다.

2026-09-15. 요청에 따른 상세 검토이며 라이선스 변경/새 허락의 발효 문서가 아니다.
현재 FSL과 GPL 적용 범위는 유지된다. 실제 권리자 확인 및 최종 계약 문안의
법률 검토는 별도다. [기존 감사](LICENSE_AUDIT_ko.md)의 소스/이력을 기준으로 한다.

## 현재 구조와 권장 방향

사용자 요구 확정(2026-09-15): **MF Detect Star만 판매용 제품에 사용할 때
본인의 허락을 받도록 하고, PiFinder에서 수정한 부분과 외부 코드는 원래
라이선스를 따른다.** [정책 및 적용 범위](MF_COMMERCIAL_POLICY_ko.md)가 현재
판단 기준이다. 아래 A/B는 비교를 위해 남기는 대안이며 선택하거나 권장하지 않는다.

PiFinder와 Python 통합 코드(GPLv3)가 `ctypes.CDLL`로 native MF(FSL)를 같은
프로세스에서 불러온다. 현재 요구에 맞추려면 **C의 독립 프로그램 구성 또는
유효한 GPL 연결 예외**를 검토해야 한다. 현재 직접 연결의 배포 문제는
아직 해결되지 않았다. MF에 GPL 선택권을 주는 것으로 처리하지 않는다.

앞서 제안한 이중 라이선스는 상용 사용 승인제와 양립하지 않는다. GPL 경로로 받은 MF는
그 조건을 지켜 상업적으로 수정·재배포할 수 있다. 제작자가 하드웨어와 소프트웨어를
판매하는 것도 허용되지만, 소프트웨어 수령자의 GPL 권리를 제한할 수 없다.
GPLv3 §5/§10의 결합 배포·추가 제한 조건에 따른 판단이다.
[GPLv3](https://www.gnu.org/licenses/gpl).

## 선택안 비교

| 방안 | 현재 ctypes 유지 | MF의 경쟁 사용 제한 | 필요한 조치 |
|---|---|---|---|
| **FSL 또는 GPLv3 이중 라이선스** | 가능 | GPL 선택 사본에는 적용 불가 | MF 권리자가 GPL 선택권을 추가하고 결합물은 GPL 경로로 배포 |
| **과거 MIT native 사용** | 가능 | 그 MIT 사본에는 적용 불가 | 실제 MIT 커밋/고지/빌드 출처를 명시, 새 FSL 전용 변경을 섞지 않음 |
| **PiFinder 측 연결 예외** | 예외 범위 안에서 가능 | MF FSL 조건을 별도로 유지할 여지 | 영향을 받는 기존 GPL 코드의 권리자들로부터 유효한 예외 확보 |
| **독립 프로그램으로 분리** | 변경 필요 | 별개 저작물로 인정될 경우 유지할 여지 | 일반 인터페이스·독립 사용/교체성·배포 구조와 실제 결합 정도 검토 |
| **FSL 그대로 + 본인에게만 상용 허락** | GPL 문제 해결 안 됨 | 유지 | MF 허락만으로 제3자 GPL 조건을 면제할 수 없음 |

권리자는 자기 코드를 복수 라이선스로 제공할 수 있다. 반대로 기존 제3자 GPL
코드에 연결 예외를 부여할 권한은 단순한 포크 소유권이나 유지관리자 지위에서
생기지 않는다. MF 쪽에만 "PiFinder 연결 허용"이라고 쓰는 것으로도 부족하다.
[FSF 복수 라이선스](https://www.gnu.org/licenses/gpl-faq.en.html#HeardOtherLicense),
[FSF 연결 예외](https://www.gnu.org/licenses/gpl-faq.en.html#GPLIncompatibleLibs).

## A. 미선택 대안: 이중 라이선스의 구체적인 변경

아래는 **선택 후 적용할 설계안**이다. 설명용이며 현재 허락을 새로 부여하지 않는다.

1. MF native의 실제 권리자와 외부 기여의 재라이선스 권한을 확인한다.
   Git 작성자 표시와 `PiFinder contributors`라는 일반 표기만으로 확정하지 않는다.
2. 권한이 확인된 native 파일만 아래 선택형 SPDX로 표시한다.

   ```text
   LicenseRef-MFDS-FSL-1.1-MIT-5year OR GPL-3.0-only
   ```

   `OR`가 선택권이다. 두 조건을 동시에 지키라는 `AND`로 쓰면 해결되지 않는다.
3. LICENSE/LICENSING.md에서 파일 범위와 선택권을 명시하고 FSL 원문과 GPLv3
   전문을 모두 제공한다. 기존 GPL 통합 코드와 Apache solver를 FSL로 바꾸지 않는다.
4. PiFinder 제품은 GPL 선택 경로로 빌드·배포한다고 릴리스 자료에 명시한다.
   MF standalone의 FSL 선택 경로와 구분하지만, 이미 GPL로 제공한 동일 사본에
   경쟁 금지·특정 업체 전용·개인 이용 전용 같은 조건을 추가하지 않는다.
5. pinned PiFinder/MF 소스, 필요한 빌드/설치 자료, 원래 고지와 GPL 전문을
   제품의 대응 소스로 제공한다. 사용자 제품의 설치 정보가 필요한 조건도 검토한다.
   업데이트마다 실제 바이너리와 소스 버전이 대응해야 한다.
6. 이후 기여에도 필요한 권한을 유지할 정책을 마련한다. 미래 버전을 다른
   조건으로 제공하더라도 이미 적법하게 제공한 GPL/MIT 사본의 권리를 회수하지 않는다.

별도 로열티나 "우리 제품에서만 실행" 약정을 GPL 사용 조건으로 붙이는 방식은
이 경로와 맞지 않는다. 제품 판매와 지원 서비스 계약은 가능하지만 GPL 권리를
제한하는 수단으로 삼을 수는 없다. [GPLv3 §6/§10](https://www.gnu.org/licenses/gpl).

## B. 기존 MIT 경로의 현실적 의미

native의 `4763a01c1b23c5a0a60ddbfd208f5d18df89c2f6`은 MIT로 제공됐고,
점검한 현재8개 native 파일과 SPDX 머리글을 제외하면 동일하다. 검출 성능을
낮춘 이전 알고리즘으로 되돌아갈 필요가 없다는 뜻이다. 최신 Tetra3 속도 개선은
별도 Apache/GPL 코드이므로 유지할 수 있다.

제품용 native를 이 MIT 출처에 명확히 연결하고 고지를 보존하는 방법은 가능하다.
단지 현재 FSL 파일에서 고지를 지워 MIT라고 부르는 방식으로 처리하지 않는다.
또한 이후 FSL 전용 변경까지 자동으로 MIT가 되는 것은 아니다.

이미 MIT로 공개한 코드에는 타 업체의 상용 사용 가능성도 열려 있다. FSL로
이름표를 바꿔 과거 코드의 권리를 소급 제한할 수는 없다. 따라서 현재 알고리즘의
독점적 상용 제한을 FSL만으로 새로 확보할 수 있다고 기대하면 안 된다.

## C. 현재 검토 방향: MF의 별도 상용 사용 조건 유지

현재 FSL은 모든 판매용 제품의 사전 승인을 요구하는 문구가 아니다. 경쟁 사용의
범위와 5년 뒤 MIT 허락을 포함한다. 더 넓은 판매용 제품 승인제를 원한다면
별도 문안을 정해야 하며, 이미 부여한 MIT/FSL 권리를 소급 제한하지 않는다.

PiFinder 쪽 유효한 연결 예외를 얻거나, MF를 독립 프로그램으로 설계하는 경로를
검토해야 한다. 어떤 권리자의 어떤 부분에 예외가 필요한지는 코드 이력에 따라
달라지므로 한 사람의 승인으로 충분하다고 단정할 수 없다.

분리 설계의 검토 후보는 공개된 일반 이미지 입력/별 좌표 출력 형식, 다른
검출기로의 교체, PiFinder 없이 사용하는 CLI/서버, 독립적인 배포·실행이다.
하지만 별도 프로세스·소켓·컨테이너라는 사실만으로 별개 저작물로 확정되지 않는다.
서로의 내부 상태·자료구조를 얼마나 공유하고 전용으로 의존하는지까지 검토해야 한다.
[FSF 결합 판단](https://www.gnu.org/licenses/gpl-faq.en.html#MereAggregation),
[SFLC의 컨테이너/GPL 분석](https://downloads.softwarefreedom.org/2019/annual-conference/sflc-2019-cle.pdf).

기술적으로는 persistent worker와 이미지 전달 방식 등을 설계하고 현재 ctypes와
같은 기록 영상에서 검출·솔빙·p95를 비교해야 한다. IPC 전환이 얼마나 느려질지는
측정 전 확정할 수 없다. 지금은 속도 최적화와 안정화된 스케줄을 변경하지 않았다.
독립 MF의 FSL은 별도로 준수하며, 이 논리는 다른 저작권자의 Cedar Detect를
무조건 제품에 넣을 허락이 되는 것도 아니다.

## 실행 순서

설치·갱신·이미지 정리는 PiFinder의 `docs/CEDAR_FREE_MERGE_ko.md`와 검사 도구로
병합/배포 단계에 연결했다. 이는 상용 사용 허락이나 GPL 결합 문제의 해결을
뜻하지 않는다. 사용자 요구에 따라 **C의 권리·구조 검토를 먼저 진행하는 방향**으로
권장안을 수정했다. MF의 정확한 허락 문안과 범위를 확정하고 배포 구조를 검증한
후 적용한다. 이번 문서 수정으로 기존 LICENSE나 실행 구조는 변경하지 않는다.
