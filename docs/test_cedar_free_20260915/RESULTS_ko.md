## 결론과 적용 범위

두 저장소의 `test/cedar-free-20260915`에 독립 테스트 소스, 재현 도구, 단계별 문서와 집계 결과를 저장했다. 운영 두 저장소는 main의 원래 커밋을 유지한다. 운영 pifinder.service는 PID 719, `/home/pifinder/PiFinder/python`에서 계속 실행 중이며 서비스 재시작·전환·영구 부팅 설정 변경은 하지 않았다.

테스트 기본값은 **SEP+기존 광해 전처리**다. 자체 `mf_detect_star` C++ 검출기를 ctypes ABI로 연결하고 배경 보간·필터 계산을 최적화했다. `PIFINDER_DETECTOR=mf`로 선택할 때 binning=2, sigma=4.5, 최대48개, response 순서, 원본 좌표 재측정 비활성이 기본이다. response 순서는 개발 자료에서 flux 순서보다 RMSE가 개선됐고 별도의 현재120장으로 검증했다. SEP보다 항상 빠르거나 정확하다고 결론 내릴 수 없으므로 운영 기본값으로 승격하지 않는다.

Cedar Detect 실행파일·서비스 설치·클라이언트 호출은 테스트 소스에서 제거했다. 솔버는 cedar-solve의 Apache-2.0 코어를 출처/라이선스와 함께 vendor했으며 Detect 관련 부분은 제외했다. 기존 `cedar_*` 기하 helper, 비활성 분기, 설정·CSV 열 이름은 호환성을 위해 일부 남는다. 이는 상용 배포 전체의 법률 검토나 모든 의존성 라이선스 감사가 완료됐다는 뜻은 아니다.

## 자체 검출기 정확도

검출기 비교는 저장된 동일 전처리 프레임에 같은 Tetra3 cascade와 품질 게이트를 적용했다. 후보 좌표뿐 아니라 후보 선택/순서가 RMSE에 영향을 줬다. 원본 aperture/Gaussian-window 좌표 재측정과 후보16/24/32개 제한은 이득이 없어 기본 적용하지 않았다.

|---|---:|---:|

| 구름 RMSE 중앙값 / p95 | 59.68″ / 101.84″ | 59.38″ / 97.97″ |

좌표 산포는 실제 기록 경과시간에 대해 RA·Dec의 선형 이동을 제거한 반경 잔차다. 독립 검증 산포 최대값은 SEP40.83″/MF49.07″였다. 두 방식 좌표 차이 중앙값8.22″, p9523.06″, 최대30.31″. 하늘 기준 정답 좌표가 없으므로 RMSE나 산포를 절대 pointing 정확도로 해석하지 않는다. 캐시 비교에는 게시단계 smoothing/continuity가 적용되지 않았다.

개발180장의 산포 p95는 SEP31.91″/MF42.99″로 반대 경향도 있었다. 따라서 단일 세션만으로 우열을 일반화하지 않는다. 같은 개발 자료의 SEP 성공 수가 실행별172~175로 달랐는데 동시 CPU 부하와1000ms 솔브 제한이 영향을 준다. 최종120장 검출기 비교는 다른 무거운 실험 종료 후 수행했으며 운영 서비스는 계속 실행됐다.

Cedar와 동일 프레임·동일 부하 조건으로 실행한 직접 A/B는 이번 변경에 포함하지 않았다. 운영 솔루션 스냅샷은 원본과 원자적으로 짝지어지지 않으므로 Cedar 대비 몇%라는 수치는 제시하지 않는다.

## 속도와 GOTO

Native 변경 전/후 라이브러리의 동일24장 교대 측정에서 후보 수·좌표·flux는 완전히 같았다. 코어 시간 중앙값118.89→96.14ms(약19% 감소), p95149.22→122.57ms. 전처리 누적 계산은 시간창 임시 배열과 float16 반복 변환을 줄였다. 실제10장의 출력/evidence/진단값이 모두 동일했고 중앙값3358.52→3158.69ms, p954206.15→3393.04ms였다. 이 전후 수치는 동시 실험 부하가 있는 환경의 값이다.

최종 독립 검증의 검출 시간 중앙값은 SEP67.58ms/MF78.04ms, 솔브 시간 중앙값21.10ms/20.68ms, 솔브 p95185.18ms/103.86ms였다. 자체 검출 자체는 SEP보다 조금 느리며 후보 선택에 따른 솔브 꼬리 지연 개선이 일부 상쇄한다.

별도12장 순차 RAW 재생에서 운영과 같은 scale worker3개로 측정했다. 준비1장 제외 두 방식11/11 성공, worker1 캐시와 출력 픽셀이 모두 같았다.
