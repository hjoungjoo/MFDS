# 다단계 해상도와 별 주변 ROI 탐색 — 최종 비교

## 결론

제안한 방식은 실제 영상에서 검출 시간을 줄였다. **전체 1/4 해상도에서 찾고 후보 주변만 1/2 해상도로 확인**하는 방식이 정확도·속도의 균형이 좋았다. 독립 검증119장과 구름 평가102장에서 기존 MF와 동일하게 모두 솔빙에 성공했다. 검출 시간은 각각52.93→23.93ms(55% 감소, 2.21배), 54.60→18.80ms(66% 감소, 2.90배)로 줄었다. 검출+솔브도 빨라졌다.

추가 원본 해상도 단계는 구름 자료 RMSE에는 이득이 있었지만 독립 검증 RMSE에는 없었다. 모든 장면의 정확도를 일관되게 높이는 선택으로 보기는 어렵다. 1/8 축소는 후보 소실이 심해 구름에서9/102만 성공했으므로 현재 구현에서는 채택하지 않는다.

전처리가 큰 비중을 차지하므로 **전체 계산 비용 개선은 별도12장 측정에서 약2.5%**였다. 검출 시간2~3배 개선을 전체 서비스2~3배 개선으로 해석하면 안 된다. 실험 옵션만 추가했고 SEP 기본값, 기존 MF 기본1/2 검출, 운영 서비스와 부팅 설정은 유지했다.

## 적용 방식

여기서 해상도 비율은 가로·세로 각각의 비율이다. 같은 노출의 전처리 영상을 단계적으로 읽는다. 실제 카메라 해상도·광학 화각·노출을 바꾸거나 이전 프레임의 별 위치로 탐색을 제한하지 않는다.

```text
전처리 영상 1920×1080
  └─ 전체 480×270에서 후보 탐색 (4×4 블록 평균)
      └─ 후보마다 원본 좌표의 64×64 영역만 읽기
          └─ 32×32로 검출 (2×2 블록 평균) → 전체 센서 좌표로 복원
              └─ 선택 사항: 후보의 32×32 영역을 원본 해상도로 재검출
```

기존 MF도 이미 전체960×540(1/2)에서 검출한다. 이번 차이는 더 낮은 해상도로 전체 탐색을 줄이고 후속 높은 해상도 연산을 후보 주변으로 한정한 것이다. ROI 시작점을 짝수로 맞춰2×2 축소 격자의 위상을 유지하며, 원본 row stride를 그대로 읽어 전체 고해상도 복사를 피한다. 솔버에는 전체 센서 좌표와 기존 FOV를 그대로 전달한다. 하나의 좁은 crop 좌표를 원래 FOV로 잘못 해석하지 않는다.

후보 최대128개에서 시작해 기존 필터를 거친48개까지 사용한다. 낮은 해상도에서 놓친 별은 후속 ROI 단계에서 복구할 수 없다. 이 한계를 드러내기 위해 이번 비교에는 실패 시 전체 탐색 재시도를 추가하지 않았다. 4×4/8×8 첫 단계는 별이1개 coarse pixel에 들어갈 수 있어 최소 support를1로 낮췄고, 후속2×2 단계에서는 기존 morphology 검사를 적용한다. ROI가 영상 끝을 넘지 않게 제한하고 중복 좌표를 제거한다. full 단계는2×2 후보의 flux/순서를 유지하고 중심 좌표만 교체한다.

## 데이터와 비교 조건

개발은 기존 current 앞31장 중 준비1장을 제외한30장이다. 이후 설정 변경 없이 validation119장과 cloud의16장 이후 평가102장을 검사했다. 동일 전처리 캐시·왜곡·FOV·최소매칭 품질 게이트를 공유하고, 프레임마다 실행 시작 방식을 순환해 순서 편향을 줄였다. 각 자료/방식은1회 재생했으며 실행 중 운영 서비스는 계속 동작했다. 독립 반복 세션/부트스트랩 신뢰구간까지 측정한 결과는 아니다.

새로 영상을 촬영하거나 카메라 설정을 바꾸지 않았다. 전처리 캐시는 이전 검증에서 기록한 프레임이며 여기서 '원본 해상도'는 전처리 영상의 전체 해상도다. 비전처리 RAW에서 탐색해 RAW ROI만 전처리하는 구조는 이번 범위에 포함하지 않는다.

## 전처리 포함 계산 비용

같은 validation 처음12장을 RAW부터 순서대로 전처리했다. 준비1장 제외 각11회, 모든 방식11/11 성공. worker3개, 전처리는 공통1회 수행한 시간을 각 방식에 더했고 검출 실행순서를 교대했다. 전처리 출력은 worker1 캐시와 픽셀 단위로 동일했다.

| 방식 | 전체 중앙값 / p95 / 최대 |
|---|---:|
| SEP | 1148.23 / 1431.49 / 1568.10ms |
| 기존 MF 전체 1/2 | 1120.19 / 1392.46 / 1479.17ms |
| 전체 1/4 → ROI 1/2 | 1092.73 / 1373.86 / 1457.61ms |
| 전체 1/4 → ROI 1/2 → ROI 원본 | 1098.70 / 1371.75 / 1462.32ms |

공통 전처리 중앙값1061.82ms다. 기존MF 전체1120.19ms에서4→2는1092.73ms로 약27ms(2.5%) 줄었다. 이전 문서의 약1.8초와 비교해 차이를 이번 코드의 효과로 계산하지 않는다. 이번 실행의 시스템 부하가 다르므로 같은 실행 안의 A/B를 사용한다. 이 값은 노출/IPC/SQM/RAW fallback/결과게시/마운트 이동을 제외한 계산 비용이며 GOTO 완료시간이나 최악 지연 보장이 아니다.12장은 p95를 안정적으로 추정하기에는 작은 표본이다.

큰 전체 속도 향상을 내려면 공통 전처리의 다단계화/영역 제한도 별도로 검토해야 한다. 다만 현재 전처리는 넓은 영역의 광해 배경과 시간 누적을 사용하므로 ROI만 잘라 같은 출력을 얻는다고 가정할 수 없다. 이번 작업에서는 이 부분을 바꾸지 않았다.

## 구현·검증·재현

- C++ 합성6/6, Python detector/SEP runner26개 통과.
- mypy 변경 모듈1파일 통과, Ruff 검사/포맷371파일 통과.
