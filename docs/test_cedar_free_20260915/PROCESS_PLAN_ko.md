# MF 독립 프로세스·공유 메모리 전환 계획

2026-09-15 작업 전 기록. 사용자 요청에 따라 테스트 브랜치 기본 검출 경로를
독립 native 서버로 전환한다. 운영 서비스와 부팅 경로는 변경하지 않는다.

- MF만으로 빌드·실행되는 C++ 서버를 추가한다. PiFinder/GPL 코드는 서버에 넣지 않는다.
- Linux memfd 공유 메모리에는 uint16 이미지 바이트만 둔다. 제어 파이프로 크기,
  검출 옵션, 요청 번호·시각을 보내고 별 좌표·flux와 알고리즘 시간을 받는다.
- 서버와 버퍼는 호출 스레드별로 재사용한다. RAW와 전처리 검출의 동시 실행,
  기존 동기 복구/정렬/보정 정책을 보존한다.
- EOF, 잘못된 응답, 요청 번호 불일치, timeout을 탐지하고 worker를 정리한다.
  기존 SEP 보조 정책을 유지하고 다음 호출에서 서버를 다시 시작한다.
- 직접 ctypes 호출은 명시적 비교 모드로 남긴다. 기본 프로세스 경로가 실패해도
  ctypes를 암묵적으로 로드하지 않는다.
- 모든 검출 모드의 좌표/flux 일치, 반복/병렬/종료/강제 중단/timeout/형상 변경을
  검증한다. 기록 RAW·전처리 영상에서 검출·솔빙 median/p95와 품질을 비교한다.
- 프로세스 분리는 기술적 조치이며 GPL 결합 적합성의 자동 확정을 뜻하지 않는다.
  실제 LICENSE는 변경하지 않는다. 구현/검증 결과와 한계는 후속 문서에 기록한다.
